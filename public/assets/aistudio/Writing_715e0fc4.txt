MASTER PROMPT — IET DAVV Personal Attendance Tracker APK


Build a polished, fully functional prototype of an Android-first personal attendance tracking app for students of Institute of Engineering and Technology, Devi Ahilya Vishwavidyalaya (IET DAVV), Indore.


The app must help students track their daily classes, labs, workshops, academic holidays, personal attendance percentages, and subject-wise attendance. It should feel like a premium, minimalist application inspired by the visual design principles of CRED: sophisticated, dark, tactile, spacious, and highly polished.


Take inspiration from the aesthetic principles, not the branding, logo, or copy of any existing app.


Do not ask me questions. Make reasonable assumptions, document them briefly, and build the complete working prototype.

Build a real, interactive application rather than static UI mockups.

- React with TypeScript.
- Tailwind CSS for styling.

6. GEOFENCING AND CLASS LOCATIONS


Create a location-validation system so students can record attendance only when they are physically near the designated classroom, lab, or workshop.


Each location should have:


- A location name.
- Optional building or block identifier.
- Latitude and longitude.
- A configurable geofence radius.
- An optional location description.


Different classes can have different locations. A lab and a lecture hall must not be assumed to be in the same place.


Geofence behaviour


When the student chooses Attended:


1. Request location permission when needed.
2. Obtain the device's current coordinates.
3. Calculate the distance between the current coordinates and the configured class location.
4. Determine whether the student is within the permitted radius.
5. Check location accuracy against a configurable tolerance.
6. Permit the attendance entry only when the validation conditions are satisfied.


Use a suitable distance calculation such as the Haversine formula.


Make the geofence radius configurable, with a reasonable initial demo value such as 80 metres. Do not treat that example as an official college requirement.


User feedback


If the student is inside the geofence, show a subtle confirmation:


"Location verified"


If outside the geofence, show:


"You're outside the permitted class location."


If permission is denied, coordinates are unavailable, or location accuracy is insufficient, explain what went wrong and provide a retry action.


Do not automatically mark the student absent merely because GPS fails.


Demo requirements


Since this is a mock-data prototype:


- Provide a clearly labelled Demo location mode.
- Allow the developer or tester to simulate being inside or outside a configured geofence.
- Keep simulated results visually distinguishable from real device location checks.
- Never present simulated GPS as real physical verification.
- Do not implement location spoofing or falsely claim that browser-based location simulation is secure.


For an actual APK, use a suitable native location implementation through Capacitor or another Android-compatible approach.


A map is optional for the prototype. CARTO, Google Maps, or an OpenStreetMap-based library may be used for visualization if appropriately configured, but a map API is not necessary for the basic distance check. Avoid requiring paid API keys for the demo.


Do not send personal coordinates to an external server. Keep location data local unless the student explicitly opts into a future feature that requires otherwise.

9. MONTHLY ATTENDANCE ANALYTICS


Below the month calendar, create a comprehensive but elegant monthly attendance summary.


Include these statistics:


- Total scheduled classes.
- Attended classes.
- Absent classes.
- GT entries.
- Cancelled classes.
- Monthly attendance percentage.


Use clear definitions.


Attendance percentage formula


For a selected period:


Attendance percentage = Attended classes ÷ (Scheduled classes − Cancelled classes) × 100


Exclude cancelled classes from the denominator.


Keep Absent and GT as distinct categories. By default, GT is not counted as Attended. It remains in the denominator because it is not an official attendance confirmation in this personal tracker. Make that interpretation configurable in settings if the student's intended meaning of GT differs.


Handle a zero denominator gracefully by showing "No scheduled classes" rather than NaN, infinity, or an invented percentage.


Monthly summary card


Create a premium summary section with:


- A large monthly attendance percentage.
- A subtle comparison with the previous month when data exists.
- A compact breakdown of attendance statuses.
- A small, clean chart showing attendance trends across the month.


Avoid excessive visualisations or crowded dashboards.

13. PREMIUM VISUAL DESIGN SYSTEM


Design philosophy


Restraint is the luxury.


Every screen should feel calm, confident, and uncluttered. Use fewer visual elements, generous spacing, clear hierarchy, and carefully controlled contrast.


There must be one dominant focal point per screen.


Avoid making the application look like a generic college management dashboard.


Colour system


Use these colours as design tokens:


- Main background: "#0A0A0C"
- Secondary surface: "#131316"
- Raised card surface: "#1A1A1F"
- Elevated surface: "#222228"
- Primary text: "#F2F2F0"
- Secondary text: "#8A8A93"
- Tertiary text: "#5A5A63"
- Single accent: soft mint "#7FE3C0"


Use the accent sparingly for important active states, the primary button, selected calendar dates, and key numbers.


Keep accent usage to approximately 5% of the screen or less.


Status colours may be used in small, restrained indicators when necessary for accessibility, but must not introduce competing accent colours throughout the interface.


No pure black backgrounds, blinding white surfaces, neon gradients, or excessive coloured cards.


Depth and surfaces


Use tasteful neumorphism, not exaggerated soft UI.


Raised cards and buttons should have:


- A very subtle upper-left light shadow.
- A deeper lower-right shadow.
- A fine, low-contrast inner border.
- Dark, carefully layered surfaces.
- Rounded corners between 20px and 28px.


Pressed elements should respond with a subtle inset effect.


Use pill-shaped primary and secondary buttons where appropriate.


Avoid harsh borders and heavy drop shadows.


Typography


Use Inter, Sora, or Manrope for the interface.


Use Instrument Serif or a similar refined display font for major attendance percentages and selected large headlines.


Follow a consistent type scale centred around:


"12 / 14 / 16 / 20 / 32 / 56"


Use uppercase, widely spaced section labels sparingly. Maintain generous line height, strong numerical hierarchy, and legible secondary information.


Layout


- Mobile-first layout optimised for an Android phone.
- Content width centred within a 390px phone frame on desktop.
- Full-width layouts on smaller mobile devices.
- At least 24px of outer padding for primary content areas where space permits.
- Consistent 8px spacing grid.
- Generous vertical spacing between sections.
- Four-icon maximum bottom navigation.
- A minimum 44px tap target wherever practical.


Motion


Use refined motion lasting approximately 200–350ms.


Include:


- Smooth screen transitions.
- Subtle tap compression to approximately 0.97 scale.
- Soft number-counting animation.
- Gentle card expansion.
- Small calendar selection transitions.
- Subtle skeleton loading effects.


Respect "prefers-reduced-motion".


Do not introduce bouncing cards, excessive parallax, distracting background motion, or animations that delay attendance recording.


Microcopy


Use short, calm, slightly witty copy throughout the normal interface.


The custom attendance jokes above are intentional exceptions.


Avoid unnecessary exclamation marks, verbose instructions, and emojis outside the designated humour and GT elements.
